# אילוצי עולם אמיתי

מה שצריך לזכור כשמשלבים את המערכת בפועל.

---

## מערכות Legacy קיימות

- מערכות ליבה רצות על טכנולוגיות ישנות
- לא ניתן להחליף — רק להוסיף שכבה מעל
- API-ים קיימים לא תמיד מחזירים מה שצריך
- **אסטרטגיה:** רכיבי AI-ops עובדים עם כל data shape — הם מקבלים props, לא מניחים מבנה

## שילוב חלקי בלבד

- לא כל עמוד יקבל AI
- לא כל צוות יאמץ בו-זמנית
- חלק מהעמודים ישלבו רכיב אחד בלבד
- **אסטרטגיה:** כל רכיב עצמאי, עובד בבידוד, לא דורש את השאר

## אימוץ הדרגתי

- עובדים לא אוהבים שינויים פתאומיים
- מנהלים צריכים לראות ערך לפני שמאשרים הרחבה
- IT צריך לאשר כל שינוי בפרודקשן
- **אסטרטגיה:** התחל עם demo → pilot עם צוות אחד → הרחב

## זמן הכשרה מינימלי

- עובדים עמוסים — אין זמן לקורסים
- הממשק חייב להיות מובן בלי הדרכה
- "אם צריך להסביר — זה לא מספיק פשוט"
- **אסטרטגיה:** labels ברורים, פעולות מובנות מאליהן, אפס jargon

## עומס תפעולי

- עובדים מעבדים 30-80 תיקים ביום
- כל שנייה נוספת × 50 תיקים = שעה ביום
- ממשק חייב לתמוך בסריקה מהירה
- **אסטרטגיה:** מידע קריטי בשורה ראשונה, פעולות בולטות, אפס ניווט מיותר

## Governance מוגבל

- אין צוות design system ייעודי
- אין design review process פורמלי
- מפתחים עובדים לבד על features
- **אסטרטגיה:** conventions פשוטים, דוגמאות ברורות, copy-paste friendly

## Technology Stack מעורב

- React + TypeScript בפרויקטים חדשים
- מערכות ישנות ב-jQuery / vanilla / Angular
- רכיבי AI-ops רלוונטיים רק לפרויקטים React חדשים
- **אסטרטגיה:** אל תנסה לתמוך בהכל. תמוך ב-React. השאר — בעתיד.

## אסטרטגיית שיבוש מינימלי

| עיקרון | יישום |
|---------|--------|
| אל תשנה קוד קיים | additive only |
| אל תוסיף dependencies | אפס packages חדשים |
| אל תשנה build process | אותו Vite, אותו Tailwind |
| אל תדרוש migration | import מה שצריך, מתי שצריך |
| אל תכפה conventions | הצע, אל תכפה |
